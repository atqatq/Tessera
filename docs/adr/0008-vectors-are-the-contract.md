# ADR 0008 — Vectors are the contract

- Status: accepted
- Date: 2026-09-02
- Deciders: maintainer

## Context

Two implementations (ADR 0005) need one arbiter. Prose specifications
drift; screenshots of expected output rot; "trust the Rust version"
makes the Python reference decoration.

## Options considered

1. The Rust implementation is authoritative; the reference follows it.
2. The Python reference is authoritative; Rust is generated or follows.
3. Committed vector files are authoritative data: deterministic inputs
   with expected outputs, versioned in git, consumed byte-identically
   by both implementations.

## Decision

Option 3. Vectors are data, not tests: `reference/python/vectors/*.json`,
generated by `tools/gen_vectors.py` from the Python reference, committed,
and replayed by both sides in CI. Regenerating them must produce an empty
diff — a non-empty diff is a behavioural change and belongs in the commit
message, named as such.

## Consequences

- Changing behaviour means changing vectors first, then both
  implementations — the commit that does it explains why the contract
  moved.
- Disagreements between implementations are one-cause bugs: either the
  vector, the reference, or the implementation is wrong, and the diff
  points at which.
- Vector files are append-only in spirit: renaming or re-scoping a case
  is a contract change and gets the same treatment as a behaviour change.
